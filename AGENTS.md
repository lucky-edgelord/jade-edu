# AGENTS.md: jade-edu

## Writing a course
- One JSON file. Its `format` is `jade-course` and its `version` is 1. The README describes every field, and `examples/stack-101.course.json` uses each one.
- Validate it before you hand it over: `node tools/validate.mjs validate file.json --json`, or `jade edu validate file.json`. The command exits with 0 when the file is fine. Fix every warning as well: the format expects every chapter to have a table and references.
- Keep each chapter to one idea. Give it 2–6 key points, a concept map of 4–8 links, 2–4 quiz questions and 1–3 labs.
- Write text the voice can read. Spell acronyms out in `pronounce` (`"CDN": "C D N"`). Put code in `code` blocks, because the voice skips them.
- Prefer labs that check themselves: `fill`, `order`, `match`, `code` and `python` with `tests`, and `terminal` with `tasks`. Use `webxdc` for anything interactive that those cannot do.

## Embedding and watching a learner
- Use `<jade-course src=…>`, or `mount(el, course, { onEvent })`.
- The events are `open`, `chapter`, `quiz`, `lab` (it carries `pass` and `msgs`), `lecture-done`, `exam` and `error`.
- `player.state()` returns the current chapter, the tab and the progress.
- Progress is stored in `localStorage` under the key `jade-edu:<course id>`.

## Changing the code
- `src/core/*` is generated by `tools/port.py` from Lilith Learning Lab. Change those modules there, or in the port script, then port again.
- Everything else in `src/` is hand-written and may only use relative imports, so that it works from a CDN, a folder and a webxdc alike. A test enforces this.
- The look comes from the `--jade-*` tokens of jade-agent-ui-ux; keep the Vault fallbacks in `src/style.js` in step with that project's `jade` preset.
- Pins to other stack parts live in `config` in `src/edu.js`: MicroPython and Live2D from jade-vn-engine, and the theme from jade-agent-ui-ux. When you change one, change jade-agent-stack's `compat.py` too.
- Run both test files before you commit.
